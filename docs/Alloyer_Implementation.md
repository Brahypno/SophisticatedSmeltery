# 焦褐合金炉升级

## 用户确认的边界

- 是独立的 `scorched_alloyer_upgrade`，不需要绑定控制器，不加入熔炼控制器的冲突组；可与冶炼炉、熔铸炉或嬗变炉升级共同安装。
- 复用控制器升级现有的 3×3 组件槽布局：前八格各安装一个原料储罐，第九格供燃料使用。
- 自带原生焦褐合金炉的产物罐，无需结构材料或另装储罐，不占九格组件位。
- 只处理流体合金，不占背包物品熔炼槽，也不执行生物熔炼。

## 运行与流体存取

`PortableAlloyer` 创建脱离世界的真实 `AlloyerBlockEntity`，直接使用其原生产物罐；原料由实现 `IMutableAlloyTank` 的库存视图访问。配方查找和执行交给原生 `SingleAlloyingModule`，不复制配方数量、温度、催化剂或产物算法，也不扫描相邻世界方块。原料储罐遵守 `tconstruct:alloyer_tanks` 方块标签，单个罐以实际物品流体能力持有内容。

最多八个原料罐参与同一配方；没有安装的格子提供空输入。流体始终留在储罐物品，合金成功时才经原生配方扣料，产物进入内置单流体罐。输出不兼容或放不下完整配方时不启动新燃料，不扣原料。已点燃的燃料按原生合金炉节奏继续燃烧，总开关关闭后暂停。

产物罐基础容量取实际原生控制器，扩容沿用精妙背包 Tank Upgrade 的堆叠折减倍率。移除容量升级时检查已储存产物所需倍率。

燃料位可放一个符合 `tconstruct:fuel_tanks` 标签的流体罐，或固体燃料；也可使用背包储罐升级中的流体燃料。复用 `PortableFuelModule` 的原生液体燃料配方、余量保存和温度选择，固体燃料的持续时间按原生 `ForgeHooks.getBurnTime(..., FUEL) / 4` 计算，温度与速率取原生固体燃料配置。新燃料仍按液体优先、固体回退的顺序选择。

界面保留九格组件槽和桶输入/输出行，上方分别显示产物及八个原料罐。每个流体显示区域均可持桶左键抽出、右键灌入；桶槽默认访问产物罐，可切换到原料罐 1–8，并沿用自动、灌入、抽出模式。产物罐有与背包储罐双向转移的按钮。

产物显示区域不叠加 “Output Tank” 文字。桶目标选择、加热开关、背包储罐转移均使用图标按钮，说明在悬停时显示。

加热开关位于升级卡片旁，与熔炼及浇筑升级的开关对齐；设置页内没有第二个加热开关。关闭设置页后，卡片开关仍可暂停合金及燃料消耗，并保留已付费的燃烧余量。

第九格为空时显示淡色原生火焰背景，悬停说明其为固定燃料位，可放固体燃料或燃料储罐；前八格显示对应原料罐编号与说明。

产物罐通过共享 `FluidStorageUpgrade` 接入背包流体能力、手持背包储罐交互和浇筑升级。与标准炉子同时存在时，两者持有独立流体；浇筑按标准炉液、合金炉产物、背包储罐的顺序尝试。此升级不自动从标准炉子搬运原料。

## 保存与移除

运行状态位于升级自己的 `alloyer` NBT 下，包含产物、燃料燃烧余量、原料/燃料组件和桶槽。开关、桶模式及目标也跟随升级保存。原料罐物品自身 NBT 保留其液体。

正常移除或交换升级前，必须排空产物和内部所有原料/燃料罐。独立的空罐、固体燃料和桶可随升级保存。清空配方只在产物罐为空时匹配，返回无状态的同种合金升级，并沿用合成事件返还内部物品（包括罐内流体）。

数据包重载会重建原生单配方模块，避免继续执行已删除的缓存配方。便携实例的液体变化保存到升级，取消针对世界坐标的原生同步；正常世界合金炉不受影响。

## 验证入口

- `AlloyerUpgradeGameTests`：独立安装、九格限制、原生容量、第七/八罐合金、八种原料配方、固液燃料、输出阻塞、开关、保存重载、配方重载、桶消息、管道、浇筑和移除/清空。
- `runGameTestServer build -PwithEstinker=true --offline`：包含现有炉型与可选嬗变炉的回归。
- `runClient -PalloyerSmoke --offline`：真实背包界面、3×3 槽位位置、产物罐抽桶、原料罐灌桶、合金开关及与熔铸炉共存。
- `runClient build -PalloyerSmoke -PalloyerLiquidSmoke --offline`：同样的真实界面流程，燃料改为第九格燃料罐中的岩浆，检查实际合金产物及岩浆减少。
- `runClient -PmanualTest` 后执行 `/ssmeltery_test alloyer`：提供安装熔铸炉、合金炉和浇筑升级的测试背包。
