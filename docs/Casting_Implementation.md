# 便携浇筑模块

`PortableCasting` 直接使用真实 `ICastingRecipe` 与 `ICastingContainer`，不创建浇筑方块实体，不运行世界 Tick，也不增加 Mixin。输入、独立输出和已浇入液体保存在该模块 NBT；炉内液体仍只由控制器持有，浇筑时从当前底层实际扣除。

已实现并通过原生对照测试的核心：

- 台/盆两种配方类型、原生空模具 tag、精确用液量及冷却时间。
- `assemble()` 动态产物、`isConsumed(context)` 及无红石状态下的 `switchSlots()` 原生槽位策略；保留结果 NBT。
- 半满时等待，不能移动模具或切换台/盆；只退回目标炉子可容纳的液体，满炉不丢液。
- 有效配方冷却中不能退液；冷却和半满状态保存/恢复；输出未取走时不再注液，不进入背包熔炼输入。
- 数据包移除运行配方后停止产出，保留液体并允许退回，不继续使用旧缓存。
- 退液入口也会先恢复当前世界的配方上下文：重载后尚未收到首次宿主 Tick 时，不能将正在冷却的有效配方误当成半满残液退回。

测试 `CastingGameTests` 将真实原版浇筑台/盆放在测试世界，向原版和便携模块注入相同液体，逐 Tick 对比冷却及两个槽位产物。包含可重复金模具、一次性沙模具、无模具铁块，以及原生储罐填充配方的动态 NBT/槽位交换。另检查半满退液、冷却重载、移除配方及预览缓存失效。核心测试已纳入下述完整回归。

## 背包升级与界面

用户已经确认：关闭加热后继续浇筑与冷却，有残液或正在冷却的浇筑升级不能拆下。

已注册普通 `casting_upgrade` 与高级 `advanced_casting_upgrade`，共用原生浇筑核心、容器和设置页，可安装多份，默认手动。手动按钮从炉内当前底层流体浇入一个原生配方的用量；**仅高级版**可启用自动，在有空闲输出且液体或模具变化后重试，不逐 Tick 重查失败配方。普通版界面不显示自动按钮，服务端还会检查物品等级，旧 NBT 或手工发送自动动作均不能越级。冷却始终按正常宿主 Tick 推进，不受加热开关影响。成品留在该升级独立输出槽，避免自动回炉。

GUI 提供模具槽、独立输出槽、台/盆模式图标、配方预览、浇筑流体柱、竖向冷却条及浇筑/退液按钮，高级版额外提供自动切换。预览按模具、流体、模式和配方重载失效缓存，不逐帧遍历配方。

普通版的手动浇筑按钮占满该行；高级版在同一行提供浇筑与自动切换。两版图标将原生焦黑浇筑台朝上的模型面投影到底板中心，高级边框复用精妙高级磁铁纹理的外框，不包含中心磁铁图案。没有新增图片或 Mixin，资源包中的上表面和边框纹理随模型重载生效。

普通合成是用户图中的 `BFT / CUC / FCF`：B 为焦黑铸件盆、F 为焦黑浇注口、T 为焦黑铸件台、C 为焦黑浇筑道、U 为精妙空白升级。高级合成为 ` D  / GUG / RRR`，D 钻石、G 金锭、U 普通浇筑升级、R 红石；使用精妙原生升阶状态转移并复制 NBT 为独立所有权，同时保留普通有序配方书显示。两张配方均有解锁进度。

每次实际浇入/退回液体都保存控制器和浇筑升级双方状态。浇筑模具的 GUI 改动即时保存，Tick 内合并保存；增删其他升级导致原生包装器重建时不能复制液体或丢失模具。

精妙核心的物品移除检查没有升级槽位参数，因此增加一个仅作用于浇筑升级的 `UpgradeHandler.extractItem` 入口检查。模拟提取与真实提取均逐槽检查残液；替换另由带槽位参数的原生检查保护。不锁住其他空闲浇筑升级，不修改其他升级的提取。
