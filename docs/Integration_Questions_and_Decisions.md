## 1. 开发前必须记住的决定

1. **先完成基础功能。** 首先支持 Smeltery、Foundry。以 Smeltery、Foundry、EsotericismTinker Transmute 三者研究共用架构，目标是较高兼容性和较好性能；不要将此误解为首版必须交付全部 Transmute 精细联动。
2. **一个背包只能有一个控制器升级。** 浇筑升级不额外限制数量，仍受实际背包升级槽数量约束。
3. **物品始终留在背包原槽位。** 不转移到熔炼模块内部库存，不设置另一套实际持有输入物品的隐藏加工槽。背包库存是输入物品的唯一存储来源。
4. 使用背包剩余普通库存的前 X 格参与熔炼，X 由结构材料决定并受实际槽数限制，不再逐槽选择。物品黑白名单作为后续版本扩展，当前不实现。
5. 提供控制器开关。关闭后停止加热，已有物品按匠魂原生规则冷却。
6. **投入材料后自动计算最大容量，不创建虚拟方块布局，不运行虚拟多方块扫描。** 可以使用内部空间、尺寸等数值计算；内部空间决定熔炼槽位数量。
7. 材料必须符合对应炉子的 tag，但不必按墙壁、底板用途分别配置。材料不足最小成炉用量时不能工作；没有材料时没有容量和加工空间。
8. 堆叠升级可以增加并发；当前炉液容量倍率使用精妙背包 Tank Upgrade 的折减系数，保留以后调整规则的空间。
9. **状态跟随控制器升级。** 原文“全部运行状态固定保存在背包 UUID 下、升级只存静态配置”的规定已被用户修正。最终存储方案必须满足控制器携带其自身状态的语义，不让两个控制器共享同一份运行内容。
10. **炉内熔融流体和内部燃料罐液体都必须排空，才能移除控制器。** 即使炉内金属已空，内部储罐还有岩浆也不能移除。
11. 通过**无序合成**绑定、换绑控制器，换绑返还旧控制器，原控制器物品 NBT 原样保留和处理。合成配方的具体材料暂不重要。
12. **合成更换控制器前，炉液、结构材料、加工物品、剩余燃料、浇筑任务都必须清空。** 这比仅检查移除时的炉液条件更严格，不要混淆。
13. **“空白熔炼升级”不是另一个独立的升级物品。** 它是本升级无 NBT 状态下的名字。绑定控制器后，同一个升级动态显示为“XX 升级 / XX Upgrade”，例如“冶炼炉升级 / Smeltery Upgrade”“熔铸炉升级 / Foundry Upgrade”；引用实际控制器原生名称组件。不要与精妙背包原版空白升级混淆。
14. 沿用精妙背包熔炉升级的运行位置和调度方式：玩家身上或放置在世界中时加工。
15. 燃料来源可以是背包 Tank Upgrade，也可以是安装在控制器内部的储罐方块；不把背包储罐升级设为唯一供燃料方式。
16. **合金是对应炉子的基础功能，首版应保留。** Smeltery 支持合金，Foundry 本身不支持，不能一律关闭或一律添加。
17. 继续复用控制器实际创建的原生 `MeltingModuleInventory` 及其自定义行为。当前已接入非持有型配方视图，仅原生产出成功后从真实背包扣料；验证状态见实施记录。

## 2. 对原设计草案的必要修正

| 原草案/先前解释 | 当前决定 |
| --- | --- |
| 将背包输入转移至模块实际输入槽 | 物品保留在背包原槽，适配原生模块的物品访问与完成时扣除 |
| 升级只存静态配置，运行内容固定归属背包 UUID | 状态跟随控制器升级；背包用于当前宿主和访问上下文 |
| 可能通过 GUI 更换或解除绑定控制器 | 用户指定通过合成换绑，不再重复询问其他方式 |
| 空白控制器升级是独立物品 | 同一升级无 NBT 时名为“空白熔炼升级”，绑定后动态改名 |
| 结构可能需要虚拟多方块布局及位置模拟 | 只投入材料并计算，不建立虚拟方块布局 |
| 墙壁、底板材料可能必须分别满足 | 合法材料无需区分部位用途，但总用量须达到最小成炉要求 |
| 合金可能放在高级功能阶段 | 对应炉子的原生合金纳入基础功能 |
| 基础燃料可能只能由背包储罐提供 | 也允许控制器内部安装储罐方块供燃料 |

### 容量与模块

设内部尺寸为 `x, y, z`，`INGOT` 表示匠魂自身的流体单位常量：

| 炉子 | 原生模块 | 炉液容量 | 熔炼槽数 |
| --- | --- | --- | --- |
| Smeltery | `MeltingModuleInventory` | `12 * INGOT * x * y * z` | `x * y * z` |
| Foundry | `ByproductMeltingModuleInventory` | `8 * INGOT * (x+2) * (y+1) * (z+2)` | `x * y * z` |
| Transmute | `SuperByproductMeltingModuleInventory` | `15 * INGOT * (x+2) * (y+1) * (z+2)` | `x * y * z` |

- 三者都在各自 `setStructure()` 中处理容量及熔炼库存尺寸；容量规则不是 `MeltingModuleInventory` 提供的统一接口。
- 对应多方块类负责材料判定。tag 表达材料合法性，不描述容量公式。
- 普通模块槽上限为 1，当前 Transmute 自定义模块槽上限为 2。保留原生批次数量语义，不能因此把背包整叠物品一次清空。
- Foundry 的原生副产物逻辑在主产物填充成功后执行 `handleByproducts()`，并没有统一保证全部副产物完整放入。需要如实验证，不要擅自改变产率规则。
- Transmute 自定义模块覆盖 `tryFillTank()`，保留实际实例才能保留此动态分派。

### 运行、物品访问和同步

- `HeatingStructureBlockEntity.serverTick()` 包含世界结构扫描、世界方块状态变更和网络同步，不能直接拿来作为便携炉 Tick。
- `MeltingModule.setStack()` 会在条件满足时按父 BlockEntity 坐标发送 `InventorySlotSyncPacket`。便携上下文必须处理这一同步路径。
- 原生模块内部有物品字段，并在完成时调用 `setStack(ItemStack.EMPTY)`。当前“物品留在背包”要求意味着必须适配这条路径，不能原样当成第二份实际库存，也不能把背包整叠物品清空。
- `MeltingModule.coolItem()` 有真实冷却逻辑；完成但被容量阻塞的物品也有原生重试行为。关闭开关采用原生冷却时，应核对并保留实际语义。
- `UpgradeWrapperBase` 提供开关、升级物品引用及保存回调。
- `CookingUpgradeWrapper` 实现 `ITickableUpgrade`；世界中背包的 `serverTick()` 已会调度该接口。应沿用背包自己的调度入口。
- `IStackableContentsUpgrade` 及现有堆叠升级检查可以用于容量保全；倍率模型尚待后定。

### 内部储罐方块

- TiC `TankItem` 直接暴露 `IFluidHandlerItem`，无需在世界创建储罐 BlockEntity 才能读取或消耗液体。
- `TankItemFluidHandler` 在执行注入/抽取后更新物品的储罐 NBT。
- 储罐容量可通过对应方块/物品的原生规则取得，不能将所有储罐硬编码成同一个容量。
- 因此，内部安装储罐方块供燃料在源码上有可复用的基础，但尚未实现或运行验证。

## 6. 开发前计划与边界（历史记录）

以下是开始实现前的计划，不是当前待办清单。第 1–3 项已进入实现并有 GameTest 验证；当前人工待验收项和后续模块统一见 [Implementation_Status.md](Implementation_Status.md)。

1. 继续查清三种原生模块如何直接加工背包原槽内物品，尤其是配方访问、完成时扣除、物品变化、进度重置、序列化和同步。
2. 明确按材料数量计算最大可用内部空间与原生容量的数值算法；不创建虚拟方块布局，不每 Tick 扫描结构。
3. 对照背包现有升级实现处理生命周期、持久化、燃料来源和容量检查。
4. 基础功能没有待用户立即回答的阻塞性玩法问题。只有源码无法决定且实际影响玩法的具体分歧才继续提问，届时给出具体例子。

## 7. 开始实现后的补充决定

- 空白熔炼升级当前可以使用紫黑方块占位外观；绑定后的同一物品在中间显示控制器正面，应适用于控制器模型/资源包的当前材质。
- 炉液显示沿用匠魂分层液柱，悬停显示名称和数量。
- 点击一种流体将其移到底层；浇筑从底层取液。
- 浇筑升级在界面切换浇筑台/浇筑盆模式，放入模具；支持手动浇筑和自动浇筑切换，不能默认理解成仅自动浇筑。
- 浇筑升级另有退液按钮，把已经注入但尚未执行有效配方（例如数量不足）的液体退回炉子；必须检查炉内可接收量，不能丢液或复制。
- 燃料液体属于独立的内部储罐方块/背包 Tank Upgrade；燃烧量、温度、速率由燃料组件记录，不放入物品熔炼库存，也不与炉内熔融流体混为一个库存。
- 用户要求：任何可能存在分歧的行为先提问，得到确认后再实现相关部分。
- 堆叠升级对炉液容量的倍率暂用精妙背包 Tank Upgrade 的折减系数，替代之前“尚未决定”的状态。
- 控制器本身计作一个结构方块，安装的有效储罐方块也计入结构材料用量。
- 关闭控制器后不允许熔炼产出，包括已经加热完成、此前因流体空间不足而等待的物品；不得直接沿用 `coolItem()` 对 `NO_SPACE` 的产出重试。未完成的物品仍按原生规则冷却。
- 关闭时暂停已经点燃的剩余燃烧量，再开启后继续使用。
- 燃料来源优先内部“匠魂燃料储罐”，不足时使用背包 Tank Upgrade；内部组件使用这个名称。
- 输入选择方案已更新：不再逐槽选择。X 由结构材料提供的熔炼槽数决定，并受背包剩余普通库存槽总数限制。
- 用户要求先参考储罐占列源码。查明储罐占整列、原生布局先检查及重排后缩容；用户确认熔炼升级本身不额外扣列，而是在储罐等升级占列后的剩余背包库存中，使用**前 X 格**作为熔炼槽。不再增加前后范围切换。
- 熔炼槽仍参与普通背包排序，物品移动或替换后重新匹配加工进度；拾取、磁铁等升级可以正常向这些槽位输入物品。
- Git 仓库：`https://github.com/Brahypno/SophisticatedSmeltery.git`。用户要求按合理的功能模块组分批提交，不要把所有功能积累成一个大提交。

## 8. 第一轮游戏内反馈后的修正（2026-10-24）

- JEI 和原版配方书需要直接显示控制器绑定的无序合成配方，不依靠物品提示说明。可见配方也必须保留精确的换绑返还及 NBT 保护。
- 用户已明确：绑定图标的底板使用精妙背包原版 `Upgrade Base`；空白熔炼升级仍可保留紫黑占位图。控制器需要显示正面。
- 移除额外合金开关。合金行为由实际控制器决定，不能用“含有合金模块”代替其原生许可条件。
- 加热开关放在升级模板旁，采用磁铁升级同样的按钮控件与位置。为保持关机冷却和容量保护，便携包装器继续参与宿主调度，只切换加热状态。
- 用户已明确：保留普通物品图标，只复用匠魂原版 GUI 的竖向热量条和缺温、炉满、无配方等状态；不需要立体物品渲染。
- 移除熔炼槽数量、剩余燃烧量等文本，扩大储液区，采用原生最小流体层高度，避免 1 锭或少量铜液完全不可见。
- 使用匠魂/Mantle 原生流体单位提示，默认显示锭、块、宝石等单位，Shift 显示原生 mB 提示。

- 燃料显示取当前有效储罐及流体，拿走储罐后不能继续显示旧罐温度；已燃烧的剩余热量另按原生记账保留。
